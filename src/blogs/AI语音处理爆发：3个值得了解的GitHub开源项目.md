# AI 语音处理爆发：3 个值得了解的 GitHub 开源项目

2026 年，语音 AI 明显站上了风口：多语言视频创作、语音优先的 Agent 产品、全本地运行的开源语音链路，都在快速走向成熟。如果你对语音处理感兴趣，或者正打算在自己的产品里接入语音能力，下面这 3 个 GitHub 开源项目值得了解一下——它们分别代表了「一站式创作工作台」「可自由更换零件的语音链路框架」「语音优先的 Agent 实时对话」三条路线。

---

## 01 | Voice-Pro：一个网页，把字幕、翻译、配音全包了

做一条多语言视频，很多麻烦其实都来自工具太散：先下载视频，再分离人声、生成字幕、翻译文本、合成配音，最后还要把素材重新对齐。每个步骤单独看都不难，但串起来就非常折腾。

**Voice-Pro** 把这些步骤装进了同一个 Gradio WebUI，目前在 GitHub 上拿到了约 **1.2 万 Star**。

### 核心能力

- **Dubbing Studio**：下载 YouTube 视频 → 提取音频 → 用 Demucs 分离人声 → 调用 Whisper / Faster-Whisper / Whisper-Timestamped 做语音识别和字幕生成。
- **翻译**：支持 100 多种语言，字幕、音频、视频素材都能接着往下处理。
- **配音**：Edge-TTS 和 kokoro 适合常规语音合成；F5-TTS、E2-TTS、CosyVoice 则支持**零样本声音克隆**——给一段样本声音，就能用它的音色朗读任意文本。

给播客换语言、给教程补一条英文音轨、快速生成一版带字幕的外语视频，都可以在一个界面里完成。

### 适合谁

- **内容创作者**：完整的可视化工作台，几乎零代码即可完成一条多语言视频。
- **开发者**：如果只想调用一个语音 API，这个项目的完整流程可能偏重；它更适合把常见流程做成可视化页面的场景。

### 硬件要求

- Windows + NVIDIA 显卡体验更稳；Mac 和 Linux 虽有启动脚本，但目前未经充分验证。
- AI 模型下载量约 10GB，官方建议预留 20GB 以上空间。
- 显存 4GB 起步，8GB 以上更从容。

> 开源地址：https://github.com/abus-aikorea/voice-pro

## 02 | Hugging Face speech-to-speech：把语音助手拆成四块，想换哪个模型都行

Hugging Face 开源的 **speech-to-speech**（语音到语音）目前已有约 **1 万多 Star**。它把一套语音助手拆成四个可独立更换的环节：

```
VAD（语音活动检测）→ STT（语音转文字）→ LLM（生成回答）→ TTS（朗读回答）
```

- **VAD**：判断你什么时候开始说话、什么时候停止说话；
- **STT**：把语音转成文字；
- **LLM**：生成回答内容；
- **TTS**：把回答读出来。

四个环节的实现都可以灵活更换。默认配置使用 Parakeet TDT 做语音识别，语言模型走 OpenAI 兼容接口，语音输出使用 Qwen3-TTS；你也可以换成 Whisper、Faster-Whisper、Paraformer、Kokoro、Pocket TTS 等方案。

### 适合谁

- 做桌面语音助手、智能硬件、机器人的开发者；
- 想研究一套**完全本地运行**的语音链路的人。

它提供的是可以不断换零件的工程框架，角色和应用形态都由你决定——这是它最大的价值。

> 开源地址：https://github.com/huggingface/speech-to-speech

## 03 | Qwen Audio Agent：让 Agent 边聊天边干活

语音优先的 Agent 产品正在爆发，但有一个很尴尬的体验问题：你发语音让 AI 去查资料或改文件，接下来只剩下漫长的安静——任务没结束，话也没法继续聊，体验很差。

**Qwen Audio Agent** 想解决的就是这个问题。它定位为一套**实时语音运行时**，把「前台对话」和「后台 Agent」拆成两条可以并行工作的链路：

- 你可以一边和它说话，一边让后台 Agent 查资料、调用工具或处理项目；
- 执行过程中能追问进度、取消任务，也能创建多个互相独立的任务；
- 任务完成后，结果自动回到当前对话里，不需要反复切窗口查看。

### 工程细节

- **后台 Agent**：支持 OpenCode、OpenClaw、Qoder、Kimi Code 等，Codex 和 Claude Code 也可以通过外部适配器连接；你原来配置的工具、MCP、Skill 可以继续复用。
- **交互端**：提供浏览器 WebUI、终端 TUI 和 macOS 桌面悬浮球。
- **对话模式**：macOS 默认支持带回声消除的**全双工对话**——AI 说话时你可以自然插话；Linux 和 Windows 的 TUI 默认使用半双工模式。
- **本地优先**：个人档案、需要长期记住的信息和任务状态都保存在本机。

> 开源地址：https://github.com/QwenAudio/qwen-audio-agent

## 横向对比与选择建议

| 项目 | 定位 | 核心亮点 | 适合人群 | Star |
| --- | --- | --- | --- | --- |
| Voice-Pro | 一站式创作工作台 | 下载 / 分离 / 字幕 / 翻译 / 配音一条龙 | 内容创作者 | ~1.2 万 |
| speech-to-speech | 模块化语音链路框架 | VAD / STT / LLM / TTS 任意换件 | 语音应用开发者 | ~1 万+ |
| Qwen Audio Agent | 语音优先 Agent 运行时 | 对话与任务并行，全双工对话 | Agent / 智能硬件开发者 | 快速上升中 |

一句话总结：

- 想**做视频**，用 Voice-Pro；
- 想**搭自己的语音助手**，从 speech-to-speech 的框架起步；
- 想**让 Agent 一边聊天一边干活**，试试 Qwen Audio Agent。

三条路线并不互斥——语音处理链路（VAD / STT / LLM / TTS）是底层基本功，创作工具是应用层，而语音优先的 Agent 则是把整条链路放进实时对话里。理解了这些概念，再去选项目会轻松很多。
