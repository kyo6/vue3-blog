# 博客标签用词

`column` 表示文章体裁，`tag` 表示内容主题。新文章优先沿用已有主题标签；确实出现新主题时再创建新标签。旧写法及对应的标准写法统一记录在 `src/config/tagAliases.js`，内容生成会提示仍在使用的旧写法，旧 `?tag=` 链接也由此兼容。

## 同义词：只保留一种写法

| 已停用 | 标准写法 |
| --- | --- |
| `Skill` | `Skills` |
| `端到端测试` | `E2E` |
| `Web Layout` | `布局` |
| `AI Coding` | `AI 编程` |

改名时修改文章的 Markdown front matter，并运行 `pnpm gen:content`。不要手改生成的 `content.json`。

## 范围不同：保留两个标签

- `自动化测试` 包括 `UI 自动化测试`；服务端测试文章只用前者，UI 测试文章可同时用两者。
- `布局` 包括 `响应式布局`、`Grid` 等具体布局主题；需要在两个入口都能找到的文章可同时标注。
- `AI Agent` 包括更具体的 `GUI Agent`；后者只用于图形界面 Agent。
- `设计规范` 与其中的 `Design Token` 不等同；前者覆盖完整规范，后者聚焦设计变量。
- `文字样式` 比 `文本效果` 更宽；视觉文字效果的文章可同时标注。
- `CSS`、`Tailwind CSS`、`color-scheme` 有技术关联，但不互为同义词。

列表筛选按标签精确匹配，不会自动展开上下位关系。如果读者需要从宽泛主题找到具体文章，应在文章里同时标注宽泛标签和具体标签。
