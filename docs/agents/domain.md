# Domain documentation

This is a single-context frontend repository.

- The canonical domain context, if introduced, belongs at the repository root as `CONTEXT.md`.
- Architectural decisions belong in `docs/adr/`.
- `AGENTS.md` contains operational guidance; it is not a substitute for domain decisions or implementation documentation.
- Read the root context and relevant ADRs before proposing architectural refactors. Keep them updated when a decision changes the project's terminology or structure.

Current domain language includes blog articles, docs/examples, works/demos, routes, themes, Markdown front matter, generated content metadata, and standalone public demos.
